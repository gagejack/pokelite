# General Index

Speedmon is a client-only Vite + React 19 roguelite (Slay-the-Spire-style branching node maps over a Pokémon battle sim), with Supabase as the only backend (Postgres + RLS + one Deno Edge Function; no custom server). The codebase is split along a hard boundary: `src/game/` holds pure, framework-free simulation and data — RNG, battle resolution, map generation, item/catch/shop draws, type and move tables, and per-region content configs — while `src/components/` holds React screens that consume it, and `src/lib/` holds the thin adapters between them (Supabase queries, React contexts, shared hooks, color tokens). Two invariants shape most of the code: **determinism** — every gameplay roll routes through the swappable generator in `game/rng.js` rather than `Math.random`, so a seed reproduces a whole run and daily challenges are identical for everyone; and **single-source-of-truth** — all numeric tuning lives in `game/balance.js`, all region-specific content in a `regionConfig` object satisfying the shape documented in `game/regionRegistry.js`, so generic loop code (`App`, `NodeMap`, `EliteFour`, `BattleCard`) never imports `game/regions/*` directly and adding a region means filling one object. Several game modules are deliberately import-free "leaf" modules so `node --test` and the `scripts/verify-*.mjs` harnesses can exercise them without a bundler (Node cannot import the `.png`/`.m4a` assets the Vite-side modules pull in) — this is why `moveAnimations.js`/`moveSounds.js` each have a data-only twin. Persistence is dual-path throughout: signed-in state goes to Supabase, signed-out state degrades to `localStorage`.

## Root

- `Agents.md` — repo-level agent/contributor instructions consumed by IDE coding agents. Note the casing: not `AGENTS.md`.
- `eslint.config.js` — flat ESLint config; `js.recommended` plus `react-hooks` and `react-refresh/vite`, ignoring `dist`. The `only-export-components` rule is why non-component tokens live in `lib/colors.js` rather than `lib/theme.jsx`.
- `index.html` — Vite entry document. Carries the full Open Graph / Twitter card block for link previews and a `user-scalable=no` viewport (mobile is a fixed-layout game surface).
- `package.json` — deps: React 19, `@supabase/supabase-js`, `framer-motion`, Tailwind v4 via `@tailwindcss/vite`. `test` is bare `node --test`; `build:dex` regenerates the offline Pokédex bundle.
- `tailwind.config.js` — class-based dark mode (`darkMode: 'class'`), toggled by `lib/theme.jsx` writing to `documentElement`.
- `vite.config.js` — React + Tailwind v4 plugins; no aliases or custom build config.

## public/data

- `public/data/evolutions.json` — prebuilt slimmed evolution chains keyed by species id; fetched at runtime by `game/pokemon.js` so evolution checks cost no network. Generated by `scripts/buildPokedex.mjs`.
- `public/data/pokedex.json` — prebuilt base data (name, types, base stats, sprite URLs) for every species the region configs reference; removes the runtime dependency on pokeapi.co.

## src

- `src/App.jsx` — root screen router and run-state owner: holds `screen`, region/starter/character selection, roster, bag, `mapIndex`, Speed Cash, the Supabase session, and the caught-species set. Seeds the RNG for seeded/daily runs, snapshots and restores RNG state for Resume Run, submits daily attempts, and lazy-loads `NodeMap`/`EliteFour` to keep the battle stack out of the initial chunk.
- `src/index.css` — Tailwind v4 entry plus the five `@font-face` declarations (Pixeled, Pokemon Classic, Orange Kid, Upheaval, Nebal) and the global font default; also defines the `--btn-shadow` animation the Daily menu bar's glow drives.
- `src/main.jsx` — `createRoot` bootstrap into `#root` under `StrictMode`.

### src/game

- `src/game/attackTypes.js` — hand-tuned species-id → attacking-type table for dual-type Pokémon, so `types[0]` (PokéAPI ordering) doesn't force all normal/flying birds to attack as Normal. Missing rows fall back to `types[0]`.
- `src/game/balance.js` — every numeric gameplay knob in one deep-frozen nested object (map generation, trainers, battle, items, catch, moves, economy, levels). Import-free leaf so sims and Node scripts can read it; excludes the Supabase-backed per-region damage multipliers.
- `src/game/battle.js` — headless battle resolver: `simulateBattle` runs the whole fight (turn order with Choice Scarf/Iron Ball, damage with STAB and `typeChart` effectiveness, held-item effects, decaying passive heals so an over-healing matchup can't hit the round cap) and returns a log the UI replays.
- `src/game/battleTeams.js` — region-agnostic team-generation algorithms (`mapLevelRange`, `pickLevel` weighted by depth down the map, trainer counts and team specs) operating on data passed in from a region config.
- `src/game/catch.js` — region-agnostic catch-offer draw over per-map `{ id, rarity }` pools using a per-tier budget split equally within a tier; `catchOdds` derives the display percentages for the balance dashboard.
- `src/game/dailyDerive.js` — pure daily derivation: UTC day number, `hashDateToSeed` (xmur3-style uint32), region pick, and ms-until-next-UTC-day. Import-free so it can never pull region image assets in.
- `src/game/dailyScore.js` — pure leaderboard reducers. A user's score is their best attempt ranked by `maps_cleared` DESC then attempt number ASC — elapsed time is recorded and displayed but no longer ranks.
- `src/game/evolutionChain.js` — dependency-free helpers turning raw PokéAPI chains into the slim shape the game uses (`slimChain`, `speciesIdFromUrl`, `levelUpPathTo`, `downgradeTarget`); shared by the runtime and `scripts/buildPokedex.mjs` so the two can't drift.
- `src/game/items.js` — the item catalogue plus the tier-budget drop model: per-item odds are derived (`tier budget ÷ items in tier`), never hand-tuned. Exports `pickThreeItems`, `itemIconUrl`, `tierColor`, `isRosterConsumable`, and `itemOdds` for the dashboard.
- `src/game/level.js` — account-level derivation from lifetime Speed Cash. Leaf module (imports only `balance.js`) so the threshold arithmetic is Node-testable; there is no stored level or XP column, so retuning payouts recomputes rather than drifts.
- `src/game/moveAliases.data.js` — move → nearest-visual stand-in table for moves with no animation sheet. Pure data, split from `moveAnimations.js` (which statically imports 79 PNGs) so `node --test` can read it; `moveSounds.data.test.js` asserts the sound table agrees with it.
- `src/game/moveAnimations.js` — static imports of the Gen 3 animation sprite sheets bound to move names, plus `getMoveAnimation` (frame counts and alias resolution). Vite-only; re-exports `MOVE_ANIMATION_ALIASES`.
- `src/game/moveSounds.data.js` — move name → RBY sound-file stem. Pure data with aliases inlined and by-ear substitutions for post-Gen-1 moves; the import-free twin that makes the coverage test possible.
- `src/game/moveSounds.data.test.js` — `node --test` guard that every move in `TYPE_MOVES` has a sound, that the table covers exactly the 72 authored slots, and that alias entries agree with `moveAliases.data.js`.
- `src/game/moveSounds.js` — binds `moveSounds.data.js` stems to Vite-hashed `.m4a` URLs via `getMoveSound`. Vite-only by construction; contains no logic.
- `src/game/nodeMap.js` — `NODE_TYPES` and map generation: `buildRows` lays out the branching rows from `BALANCE.map`, rolls node types, places the Pokécenter/Pokémart fork and the boss, and `resolveMysteryType` picks a Mystery node's concrete outcome. Asserts its node-type literals match `BALANCE`'s at load.
- `src/game/pokemon.js` — the Pokémon runtime: fetches and caches base data and evolution chains from `public/data`, builds leveled instances (`buildPokemonInstance`, `calcStat`, shiny/stage rolls), and owns evolution (`checkEvolution` with generation gating via `GEN_MAX_ID`, `evolveInto`, `applyBattleVictory`, `applyRareCandy`) plus move retyping helpers.
- `src/game/pokemonTypes.js` — static species-id → types table for dex 1–649, generated from PokéAPI so the Pokédex can color chips without ~649 detail requests.
- `src/game/regionRegistry.js` — maps region name → config and documents the full `regionConfig` shape in a header comment; the single seam through which all region content reaches the generic loop. Also exports `regionNames` and `allLegendaryIds`.
- `src/game/rivals.js` — resolves a RIVAL node's team by splicing the starter-countering ace (chosen from the player's pick) onto the authored specs at the roster's top level; both the battle path and the map tooltip call it so they can't disagree.
- `src/game/rng.js` — the determinism core: one swappable module-level generator, defaulting to `Math.random` and replaced by seeded mulberry32 via `seedRng`. Exports state save/restore (for Resume Run) and `withRng`/`deriveSeed` for isolated per-map streams. Imports nothing.
- `src/game/roster.js` — pure roster helpers: `swapInRoster` and the healing consumables (`healOne`, `reviveOne`, `reviveAll`), each returning `{ roster, used }` so a no-op never consumes the item.
- `src/game/seed.js` — shareable seed codec, `REGION-XXXX` with the suffix in Crockford base32 (I/L/O/U removed) so codes survive being read aloud. Imports nothing.
- `src/game/shop.js` — pure Pokémart inventory resolution: region generic list plus the map's curated list, priced and stocked from `BALANCE.economy` with an explicit per-map `stock` override. Adds no item data of its own, so shop and bag can't drift.
- `src/game/shop.test.js` — `node --test` coverage of stock precedence (explicit per-map > global table > default 1) and of unpriced items being excluded from the shelf.
- `src/game/starters.js` — region name → three starter species ids; consumed by `StarterSelect`, `RegionBar`, `Stats`, and `scripts/buildPokedex.mjs`.
- `src/game/trainerPools.js` — filters a themed trainer pool to the species unlocked by the current map via a region's `speciesMinMap`; passes the pool through unchanged if the filter would empty it, so a mis-authored table can never yield a trainer with no Pokémon.
- `src/game/typeChart.js` — the 18×18 effectiveness table as sparse per-attacker overrides (omitted = 1×) plus `getEffectiveness`.
- `src/game/typeMoves.js` — the authored move table: exactly four tiered moves per type, keyed in PokéAPI kebab-case so animation and sound lookups match, with `tierForLevel` mapping spawn level to tier. Base powers come from `BALANCE.moves`.
- `src/game/types.js` — the type → display color map shared by every chip in the UI.
- `src/game/updates.js` — patch-note content for `UpdateNotice`. Item entries are item ids resolved through `ITEMS` and feature facts quote `BALANCE`, so notes can't describe a state the game isn't in; bumping `id` re-shows the notice to everyone.
- `src/game/version.js` — the single `VERSION` string every surface reads.

#### src/game/regions

- `src/game/regions/hoenn.js` — Hoenn character-sprite imports and `hoennConfig`; content-incomplete (no authored maps), so the region renders as unavailable.
- `src/game/regions/kanto.js` — Kanto asset imports (character sprites, map backgrounds, badges) and `kantoConfig`, wiring in the data from `kanto.teams.js`.
- `src/game/regions/kanto.teams.js` — Kanto battle data: per-map trainer species pools (evolution-gated by level band), gym-leader and Elite Four teams, Blue's starter-counter tables, rival teams, and `MAP_LEVEL_RANGES`.
- `src/game/regions/regionList.js` — the five regions' display metadata (name, gen, downscaled 800px card map, box legendaries) and the PokéAPI sprite URL builder; shared by `RegionSelect` and the desktop `RegionBar` so they can't drift.
- `src/game/regions/sinnoh.js` — Sinnoh character-sprite imports and `sinnohConfig`; content-incomplete like Hoenn.
- `src/game/regions/unova.js` — the reference region implementation: assets, per-map catch pools, legendary pools, themed per-trainer-class species pools with `speciesMinMap` gating, and `unovaConfig`. Maps 6–8 borrow Kanto backgrounds pending Unova-native art.
- `src/game/regions/unova.teams.js` — Unova battle data: the fallback per-map trainer pools (every Unova class has a themed pool, so this is a safety net), boss and Elite Four teams, and `MAP_LEVEL_RANGES`.

### src/lib

- `src/lib/AnimatedHpBar.jsx` — HP bar that eases width and color between values via a double-`requestAnimationFrame` commit, and snaps instead of animating when `maxHp` changes (a different Pokémon took the slot). Exports `hpColor` for callers that tint text to match.
- `src/lib/colors.js` — WCAG-checked shared color tokens (`muted`, `cash`, `cashShort`, `twoTone`, stat-bar shades), each returning a light/dark pair. Lives outside `theme.jsx` so that file's Fast Refresh keeps working.
- `src/lib/daily.js` — daily-challenge data layer: composes `dailyDerive` + `dailyScore` + the seed codec with Supabase reads/writes for attempts and the leaderboard, and joins in account XP through the `user_levels` RPC (a failed level lookup degrades to xp 0 rather than dropping the board). Re-exports the pure reducers as the single import site.
- `src/lib/regionBalance.js` — cached per-region `{ player, enemy }` damage multipliers from the `region_balance` table, read synchronously by battle call sites and falling back to the region config's `damageMultiplier` when the fetch fails. `saveRegionBalance` is the admin write, clamped to `[0.25, 5]`.
- `src/lib/runSave.js` — Resume Run persistence. Upserts the whole snapshot (region, roster, bag, map layout, node progress, RNG state, counters) to `saved_runs` for signed-in users and to `localStorage` otherwise; `clearRun` wipes both stores so a stale copy can't survive a login/logout.
- `src/lib/settings.jsx` — context for `battleSpeed` and `autoClose`, both mirrored to `localStorage` on write.
- `src/lib/sound.js` — SFX playback. `playSound` takes a registry key, `playSoundUrl` takes an already-bundled asset URL (move SFX); both share one `Audio` element per key so a retrigger rewinds instead of layering, and both swallow autoplay-policy rejections. Mute state lives in `localStorage`.
- `src/lib/supabase.js` — the shared client, constructed from `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`.
- `src/lib/theme.jsx` — dark/light context; dark is the default (only an explicit `'light'` opts out), toggling the `dark` class on `documentElement` for Tailwind. `cards` is permanently true — panels use the dark scheme in both modes because the app sits over a background image.
- `src/lib/updateSeen.js` — one `localStorage` key holding the last-dismissed `UPDATE.id`, so publishing a notice is just bumping that id and storage never accumulates a key per release. Every access degrades to "not seen" when storage throws.
- `src/lib/useEvolutionFlow.jsx` — the shared post-victory pipeline for `NodeMap` and `EliteFour`: applies level-ups/heals/auto-evolutions, queues evolution notices and multi-branch choices, handles Evolve Stone and Rare Candy, and renders both popups (choices take priority over notices).
- `src/lib/useIsDesktop.js` — resize-tracking boolean at the 768px `DESKTOP_BP`, read by nearly every component to pick a layout branch.

## scripts

- `scripts/buildPokedex.mjs` — offline generator for `public/data/*.json`: bundles the region configs with rolldown (image imports stubbed) to collect every referenced species id, resolves the level-up evolution closure from PokéAPI, and writes the base-data and evolution bundles. Removes the runtime pokeapi.co dependency.
- `scripts/encodeMoveSfx.mjs` — one-time transcode of the referenced Gen 1 WAV pack to 48 kbps mono AAC (~25× smaller); `-c 1` is required because `--mix` alone does not downmix.
- `scripts/preblurRegionMaps.mjs` — bakes the region-card blur into the JPEGs **in place**, because a small-radius CSS blur rasterizes inconsistently across GPUs and DPRs.
- `scripts/verify-daily-derive.mjs` — harness for `dailyDerive.js`: day-number monotonicity, seed determinism, region rotation.
- `scripts/verify-daily-score.mjs` — harness for the `dailyScore.js` reducers over synthetic attempt rows.
- `scripts/verify-determinism.mjs` — cross-module determinism check: seeds the RNG and asserts a scenario spanning `nodeMap` + `battleTeams` reproduces byte-identically.
- `scripts/verify-evolution-downgrade.mjs` — exercises `levelUpPathTo`/`downgradeTarget` against the real shipped `evolutions.json` rather than a fixture, covering under-leveled pool entries.
- `scripts/verify-map-seed.mjs` — proves a map built from `deriveSeed(seed, mapIndex)` is identical regardless of how many shared-stream `rng()` calls preceded it (the Play Again bug). Contains hardcoded absolute paths from an older repo location.
- `scripts/verify-resume-rng.mjs` — simulates `getRngState`/`setRngState` across a mid-sequence save/restore, mirroring Resume Run.
- `scripts/verify-rng.mjs` — harness for `rng.js`: same-seed reproduction, `isSeeded`, state round-trip.
- `scripts/verify-seed.mjs` — round-trips `encodeSeed`/`decodeSeed` across boundary seeds and regions.
- `scripts/verify-trainer-pools.mjs` — harness for `filterPoolByMap`, including the never-empty-a-pool guarantee.
- `scripts/verify-unova-trainers.mjs` — validates Unova's trainer data by parsing `unova.js`/`unova.teams.js` **as source text**, since plain Node cannot resolve their `.webp` imports.

## supabase

- `supabase/daily_attempts.sql` — `daily_attempts` table, indexes, and RLS for the daily leaderboard. Trust-client model: no server-side verification, RLS is the only guard; unlimited attempts per UTC day with `attempt_no` as the tiebreaker.
- `supabase/functions/login-with-username/deno.json` — import map for the Edge Function (`std/http`, `@supabase/supabase-js`).
- `supabase/functions/login-with-username/index.ts` — Deno Edge Function that resolves username → email server-side with `service_role`, proxies to GoTrue to verify the password, and returns only session tokens. Unknown username and wrong password return an identical generic 401 so there is no existence oracle.
- `supabase/region_balance.sql` — `region_balance` table replacing each region's symmetric `damageMultiplier` with independent player/enemy knobs; world-readable, admin-writable.
- `supabase/revoke_email_rpc.sql` — revokes client grants on the old username→email RPC now that login goes through the Edge Function, closing the enumeration leak. The function definition is kept in `username_auth.sql` for rollback.
- `supabase/runs_tracking.sql` — adds the missing INSERT policy (and supporting schema) for `runs`/`catches`; without it RLS silently rejected every run-end insert, which is why the table stayed empty and the Pokédex had no catches.
- `supabase/username_auth.sql` — `profiles` table mapping auth users to a case-insensitively unique username plus signup email, its RLS, and the (now client-revoked) SECURITY DEFINER username→email resolver.

## Skipped

Deliberately omitted, with reasons:

- `package-lock.json` — generated lockfile.
- `dist/` — build output.
- `node_modules/` — dependencies.
- `graphify-out/` — generated knowledge-graph cache (currently staged for deletion).
